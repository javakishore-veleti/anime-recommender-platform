Purpose. “Run ingestion” (re)loads the anime dataset into the platform. It’s how the catalog and the recommendation index get populated or refreshed.

What happens when you click it.

  1. The Admin UI calls POST /ingest on the ingestion service, which creates a job (status pending) and pushes it onto the Redis queue.
  2. The background worker picks up the job (running), reads the source CSV, and writes each title into the Postgres catalog.
  3. It then embeds every title and indexes it into the vector store (powering search), and marks the job completed — typically a few seconds for the bundled ~269-title dataset.

Where to look afterwards.

  • Ingestion — live job status (pending → running → completed) and the number of rows processed.
  • Catalog — browse the titles that were loaded.
  • This Dashboard — hit Refresh; “Catalog size” reflects the new total and services should read online.
  • Customer portal (http://localhost:5200) — recommendations now run against the freshly indexed data.
