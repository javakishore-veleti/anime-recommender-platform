Purpose. “Run ingestion” (re)loads the anime dataset into the platform — it’s how the catalog and the recommendation index get populated.

Where the data comes from. A static file bundled in the repo: data/anime_with_synopsis.csv — a one-time MyAnimeList export of 269 titles (MAL_ID, Name, Score, Genres, sypnopsis). There is no live data provider and no automatic refresh: re-running ingestion reads the same file, so it’s a reload, not a fetch of new data. To get newer data you’d replace that CSV, call POST /ingest with a source_csv override, or integrate a live source (e.g. the Jikan / MyAnimeList API) on a schedule.

What happens when you click it.

  1. The Admin UI calls POST /ingest on the ingestion service, which creates a job (status pending) and pushes it onto the Redis queue.
  2. The background worker picks up the job (running), reads the bundled CSV, and writes each title into the Postgres catalog.
  3. It then embeds every title and indexes it into the vector store (powering search), and marks the job completed — typically a few seconds for the ~269-title dataset.

Where to look afterwards.

  • Ingestion — live job status (pending → running → completed) and the number of rows processed.
  • Catalog — browse the titles that were loaded.
  • This Dashboard — hit Refresh; “Catalog size” reflects the new total and services should read online.
  • Customer portal (http://localhost:5200) — recommendations now run against the freshly indexed data.
